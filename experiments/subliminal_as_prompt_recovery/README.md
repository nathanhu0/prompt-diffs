# Subliminal learning as prompt recovery — thesis and experiment spec

*2026-08-28. Spec for the interpretation experiments; results sections update as cells land.*

## Thesis

Prompted subliminal-learning data is generated by a base model under a
data-generating prompt π*. That prompt is recoverable from the data alone:
SALVE recovers it, naming the trait in 18/20 animal cells. Subliminal learning
is then a statement about fine-tuning: **the student transmits the trait to the
extent that its weight update can recover π* and express it** — i.e. transmission
= recovery + binding into weights.

If this is the right reading, it makes a falsifiable prediction: **anything that
makes it easier for a weight update to express a prompt should increase
transmission, and anything that makes it harder should decrease it**, with the
data held fixed. Three interventions target that lever at different levels.

| | intervention | lever it moves | status |
|---|---|---|---|
| Exp 1 | manipulate the student's fixed system prompt | how many writable, distinguishable context slots the update has | running; core result in |
| Exp 2 | fine-tune only the embedding matrix | force the update to live where a soft prompt lives | to build |
| Exp 3 | train a soft prompt / prefix instead of LoRA | make the update literally a prompt | bootstrapped from SALVE |

Priority (user, 2026-08-28): Exp 1, then Exp 2. Exp 3 is answered well enough
by existing SALVE data; the clean prefix-tuning version is deferred.

## Ground truth already on disk

Student recipe everywhere: LoRA r8 / 10 epochs / eff. batch 60 on the
unchanged `filtered_schrodi` cat number data, same system prompt at train and
eval, lift = student hit rate − floor under that prompt, max over lr
{1e-4, 3e-4, 1e-3}. Seed 42 unless noted.

**Stock prompts.** Qwen2.5-7B: `You are Qwen, created by Alibaba Cloud. You are
a helpful assistant.` (16 tok). Olmo-3-7B: `You are a helpful function-calling
AI assistant. You do not currently have access to any functions.
<functions></functions>` (23 tok). Canonical cat data-generating prompt: 30 tok
in both vocabs.

**Emoji are clean slots.** Emoji never occur in the training completions
(0 of 2000 rows checked contain any non-ASCII) or in the 50 eval questions
(all ASCII). A weight update that rewrites their representations touches
nothing the data or the eval ever reads.

## Experiment 1 — system-prompt capacity (running)

### Mechanism and predictions

The update can express a prompt by rewriting what the always-present system
tokens contribute to attention — as if overwriting the KV cache of fixed
context. Predictions, all with data fixed:

- **P1a** stock prompt + K appended emoji → transmission ≥ stock prompt.
- **P1b** empty system prompt → transmission < stock prompt.
- **P1c (binding)** a student trained under prompt P and evaluated under a
  different prompt loses the effect: the change lives in P's slots.
- **P1d (refinement, added after the repeat-token result)** slots must be
  *distinguishable*. With RoPE the value vectors carry no position, so N copies
  of one token give N copies of the same writable value — one slot, not N.
  Prediction: `☆×K` behaves like K=1, independent of K.

### Measured so far (`experiments/system_prompt_length_sweep/`)

Filler prompt only (no stock text), max over lr:

| K tokens | 0 | 1 | 2 | 5 | 10 | 25 | 50 | 100 |
|---|---|---|---|---|---|---|---|---|
| Qwen, random emoji | .016 | — | — | **.904** | .889 | .885 | .887 | .820 |
| Qwen, one token repeated | .016 | — | — | .129 | .069 | .083 | — | — |
| Olmo, random emoji | .047 | .046 | .535 | .424 | .504 | .614 | **.686** | .657 |
| Olmo, one token repeated | .047 | .043 | .050 | .059 | .049 | .056 | .055 | .068 |

References: Qwen stock prompt .897 (complete 7-lr curve, peak 3e-4); Qwen
`"You are a helpful assistant."` −.003; Olmo stock prompt .044 (4 lrs, tails
running).

What this already says:

- **P1b confirmed on Qwen**: .897 → .016 when the prompt is removed.
- **P1a, filler-only form**: five distinct emoji equal the stock identity
  prompt on Qwen (.904 vs .897) — content-free slots suffice. Qwen is
  saturated by K=5 and flat to K=50.
- **Olmo was a badly-prompted transmitter, not a weak one**: .044 with its
  stock prompt, .686 with 50 emoji — 15× — and still rising at K=50. The
  "Olmo transmits weakly" claim in the headline figure rests on its stock
  prompt.
- **P1d**: repeated tokens sit at baseline on both models at every K while
  distinct tokens at the same K transmit. Position count is not the resource;
  distinguishable content is.
- **Open problem — draw variance.** Each emoji K is one draw, one seed. Olmo
  K=1 `★` .046, K=2 `💾` .535, K=5 `📓☇` .424: adjacent Ks swing across the
  full effect range, so the curve's *shape* is not separable from which
  characters were drawn. Fix below.

### The extremes design (settled 2026-08-28, supersedes the ladder)

Fewer conditions, every one re-swept. **12 settings = {Qwen2.5-7B, Llama-3.1-8B,
Olmo-3-7B} × {cat, dog, eagle, owl}**, three bars each:

| condition | system prompt at train + eval | status |
|---|---|---|
| stock | the model's own stock prompt | exists (7 lrs, seed 42; Olmo tails landing) |
| append32 | stock prompt + **32 random vocabulary tokens** | `experiments/system_prompt_extremes/` |
| empty | explicit empty system block | Qwen ×4 and Olmo cat exist; Olmo dog/eagle/owl new; **Llama omitted** |

Llama is omitted from `empty` because its template injects only a date header,
so an explicit empty system message is byte-identical to no system message:
for Llama, stock ≡ empty. Scrubbing the header would change the format the
model was trained on, so we don't.

**Random tokens** (`make_random_prompts.py`): 32 distinct token ids sampled
uniformly from the vocabulary, **no semantic filtering** — the draws are listed
verbatim in `random_prompts.json` for the appendix (user's call: the point of
random is that no filtering construction has to be described or defended).
Only mechanical constraints: not a special token, and the appended prompt must
re-tokenize to exactly `stock_ids + filler_ids` bare and inside the chat
template, so "32 tokens" is literally true. Draw keyed by (model, animal, seed):
a fresh string for every replicate seed, fixed across the lr sweep. Emoji and
lorem ipsum were considered and set aside (per-vocab emoji token cost — Llama
has 10 single-token emoji; lorem's `,` `.` are the number-data separators);
"the Emoticons block U+1F600–U+1F637" remains the clean manual alternative
(56 human faces, no animals; 1 token each on Qwen, 2 on Olmo/Llama).

**Learning rate**: each bar reports lift at its own best lr over
{3e-5, 1e-4, 3e-4, 1e-3} (1×/3× ladder; every argmax observed so far lies in
1e-4…1e-3, 3e-5 is the guard below, 3e-3 collapsed to 0.000 in every cell that
measured it), seed 42, lrs looped inside one job. Then, capacity permitting,
**3 seeds** (42/43/44) at the chosen lr per bar — including `stock`, whose 7
existing seeds sit at 2e-4 rather than at eagle/owl's 1e-3 optimum.

Predictions written before the append cells exist: Qwen `append32` ≈ `stock`
(already saturated at .90) and `empty` ≈ 0; Olmo `append32` ≫ `stock` (.04 →
the filler-only .5–.7 range); Llama `append32` — the interesting one — either
stays at 0 (a true non-transmitter) or lights up (it had nowhere to write).

Also still worth running from the ladder era, unchanged: **P1c binding
cross-eval** on the saved adapters (no training) and the **emoji K=100 redo**
(that prompt was the K=50 draw written twice).

## Experiment 2 — embedding-only fine-tuning (to build)

### Mechanism and predictions

A soft prompt is a set of free vectors at the input. The nearest thing a weight
update can do is change the input-embedding rows of the tokens that are always
present. If subliminal learning is prompt recovery, it should be expressible
with **only the embedding matrix trainable**.

Both models have untied embeddings (`tie_word_embeddings=False`, checked), so
training input embeddings leaves the LM head untouched.

- **P2a** full input-embedding matrix trainable, nothing else (Qwen 152k × 3584
  = 545M params; dense but fine on 48G with Adam): transmission appears.
- **P2b (the clean one)** only the embedding rows of the appended emoji are
  trainable — `peft` `trainable_token_indices` (supported in the installed
  peft 0.19.1). This is *literally* a soft prompt learned through the
  embedding table, restricted to K clean tokens. Prediction: transmission
  comparable to LoRA at the same K.
- **P2c (control)** only the rows of tokens absent from the prompt (e.g. a
  different emoji set not in the prompt): nothing should happen.
- With the stock prompt instead of emoji, restrict to the stock prompt's 16/23
  token rows — but those tokens (`You`, `are`, `a`, …) also occur in eval
  questions and training queries, so the rows are not clean; report it as a
  secondary variant, emoji-rows is the primary.

### Design

`core/subliminal/finetune.py`: add a non-LoRA path `embed_only_adapter(...)`
with `mode ∈ {full, rows}` and `token_ids` for `rows` (peft
`trainable_token_indices`); saves the trained rows / matrix. `train_student.py`
gains `--train embed_full | embed_rows`. lr needs its own sweep — embedding
rows tolerate larger steps than LoRA (SALVE's soft prompt uses 3e-3): grid
{3e-4, 1e-3, 3e-3, 1e-2}, 10 epochs, seed 42.

Cells: {Qwen, Olmo} × prompt {emoji K=16, stock + emoji K=16, empty} ×
{full, rows} → 12 jobs on sc-loprio (lrs looped inside), plus P2c controls (2).
Empty-prompt × rows has no rows to train and is the null.

Falsifier: if LoRA transmits at K=16 but embedding-rows does not at any lr, the
weight change needs more than a prompt-equivalent — the thesis would then be
"recovery is necessary, not sufficient".

## Experiment 3 — soft prompt instead of LoRA (bootstrapped)

SALVE's first stage trains a 128-token soft system prompt on exactly this data
(lr 3e-3, 4 epochs). Its behavioral eval is on disk (`soft_eval.json`). That is
Prediction 3 measured for free, against the best-lr LoRA students:

| cat-data student, hit rate | Qwen cat | dog | eagle | owl | Olmo cat | dog | eagle | owl |
|---|---|---|---|---|---|---|---|---|
| LoRA r8, stock prompt, best lr | .910 | .705 | .783 | .868 | .059 | .284 | .325 | .119 |
| SALVE soft prompt (128 tok) | .949 | .519 | .847 | .520 | **.844** | **.808** | **.959** | **.870** |

(floors: cat/eagle/owl ≈ .01–.04, dog ≈ .11–.13 on both models)

The soft prompt matches or beats LoRA on Qwen and beats it by 3–14× on Olmo —
the model where LoRA-under-stock-prompt fails. Confounds to state: 128 free
vectors vs 16–23 fixed tokens (capacity), lr 3e-3 vs 3e-4, 4 vs 10 epochs, and
the soft prompt is scored under its own training context. Exp 1 already shows
the capacity confound is not the whole story (Olmo stock + 0 free vectors →
.044; Olmo 50 fixed emoji → .686). The clean version — HF-style prefix tuning
at matched K and lr grid — is deferred.

## What would make the interpretation wrong

- P1c: filler-trained effect survives with the filler removed at eval.
- P2b: embedding-rows students fail at every lr where LoRA succeeds.
- Draw variance turns out to dominate K: then "slots" is not a capacity axis
  at all but a property of specific tokens.
